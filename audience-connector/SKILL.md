# Askdepth Audience Connector Skill

The **Askdepth Audience Connector** implements an inverted, zero-data-egress architecture (**"We Query You"**):
- Raw database credentials and user tables never leave your infrastructure.
- The Askdepth platform signs constrained, read-only criteria queries with HMAC-SHA256 and sends them to the connector mounted inside your perimeter (by default at `/askdepth/v1`).
- Your connector verifies the signature, enforces column whitelisting, executes a read-only query with keyset pagination and seeded random sampling, and returns capped canonical candidate rows (`ROW_CAP = 1000`).

## 2. Quick-Start Implementation Workflow

### Step 1: Install Packages

```bash
# Using pnpm
pnpm add @askdepth/audience-connector pg
pnpm add -D @types/pg

# Or using npm
npm install @askdepth/audience-connector pg
npm install -D @types/pg
```

### Step 2: Configure Environment Variables

Set the 64-hex HMAC signing secret generated by the Askdepth platform during connector creation:

```ini
ASKDEPTH_CONNECTOR_SECRET="your-64-hex-hmac-secret"
# Optional: retain previous secret during zero-downtime secret rotation
ASKDEPTH_CONNECTOR_PREVIOUS_SECRET="previous-64-hex-hmac-secret"
# Recommended: dedicated read-only PostgreSQL connection string
ASKDEPTH_CONNECTOR_DB_URL="postgresql://readonly_user:pass@db.example.com:5432/app"
```

### Step 3: Instantiate `createConnector`

Map canonical Askdepth fields to your database columns and explicitly separate **filterable** vs **returnable** attributes:

```typescript
import { Pool } from 'pg';
import { createConnector, postgresAdapter } from '@askdepth/audience-connector';

const pool = new Pool({
  connectionString: process.env.ASKDEPTH_CONNECTOR_DB_URL ?? process.env.DATABASE_URL,
  max: 5,
});

export const connector = createConnector({
  secret: process.env.ASKDEPTH_CONNECTOR_SECRET!,
  previousSecret: process.env.ASKDEPTH_CONNECTOR_PREVIOUS_SECRET,
  basePath: '/askdepth/v1',
  adapter: postgresAdapter({
    pool,
    table: 'users',
    schema: 'public',
  }),
  fieldMapping: {
    externalId: 'id',             // Required: matches Askdepth.identify(userId) in browser SDK
    email: 'email',               // Required: valid email for research outreach
    name: 'name',                 // Optional: display name
    signupAt: 'created_at',       // Optional: ISO 8601 / timestamptz
    segment: 'segment',           // Optional: lifecycle cohort (e.g. 'vip', 'at_risk')
    isActive: 'is_active',        // Optional: boolean activity flag
    contactable: 'marketing_opt_in', // Optional: boolean opt-in flag
  },
  attributes: {
    // Max 10 filterable attributes allowed in criteria (`attr.<name>`)
    filterable: ['loyalty_tier', 'preferred_category', 'device_type', 'country'],
    // Returnable must be a subset of filterable. Omitted attributes ('country') are filter-only!
    returnable: ['loyalty_tier', 'preferred_category', 'device_type'],
  },
});
```

### Step 4: Mount the HTTP Route or Framework Shim

The connector exposes a Web-standard `{ fetch: (request: Request) => Promise<Response> }` interface and automatically serves four endpoints under `basePath` (`/askdepth/v1`):
- `GET /askdepth/v1/health` — Negotiates `contractVersion` (`1.0.0`) and capabilities.
- `GET /askdepth/v1/schema` — Returns introspected or declared column names and types.
- `POST /askdepth/v1/candidates/count` — Returns `{ count: number }` matching criteria.
- `POST /askdepth/v1/candidates/search` — Returns `{ rows: CandidateRow[], nextCursor?: string }`.

For framework-specific mounting (Next.js App Router, Express, Fastify, AWS Lambda, Cloudflare Workers), see **[PostgreSQL & Framework Integrations](./references/postgres-and-frameworks.md)**.

## 3. Critical Rules & Common Pitfalls

1. **Preserve Raw Request Bytes for HMAC Verification**:
   - HMAC-SHA256 is computed over `${timestamp}.${rawBody}` (or `${timestamp}.` for `GET`/`HEAD`).
   - **Express**: You **MUST** mount `app.use(express.raw({ type: 'application/json' }))` before `expressHandler(connector)`. Never use `express.json()` on the connector route—it discards raw bytes and causes `expressHandler` to fail with HTTP 500 (`shim_misconfigured`).
   - **Next.js Proxy / Middleware**: In `proxy.ts` or `middleware.ts`, bypass `/askdepth/v1` immediately (`if (pathname.startsWith('/askdepth/v1')) return NextResponse.next();`) so middleware does not mutate headers, bodies, or sessions.
2. **Never Map Sensitive or Special-Category Columns**:
   - Leave internal/secret columns (such as `password`, `password_hash`, `internal_notes`, `crm_account_id`) completely out of `fieldMapping` and `attributes`. Conformance case **N3** verifies they never leak.
   - At startup, `createConnector` scans all mapped columns and attribute names against a strict GDPR Special-Category regex (`health`, `medical`, `diagnos`, `religio`, `political`, `ethnic`, `race`, `sexual_orientation`, `gender_identity`, `biometr`, `genetic`, `trade_union`, `disabilit`). Any match throws immediately and prevents startup.
3. **Filter-Only vs. Returnable Attributes**:
   - Attributes listed in `attributes.filterable` (max 10) can be queried via `attr.<name>`, but are **not returned** in candidate row payloads unless also listed in `attributes.returnable`.
   - Every `returnable` attribute must also be listed in `filterable`.
4. **Zero-PII Identity Bridging (`externalId`)**:
   - The `externalId` column mapped in Audience Connector must match the exact `userId` passed to `askdepth.identify(userId)` in the browser SDK (`@askdepth/core` / `@askdepth/react`). This allows Askdepth to correlate frontend friction sessions with backend customer records without sending PII from the browser.
5. **Cloudflare Workers Compatibility**:
   - `@askdepth/audience-contract` uses `node:crypto`. When deploying to Cloudflare Workers, always set `compatibility_flags = ["nodejs_compat"]` in `wrangler.toml`.

## 4. Verification & Conformance CLI

Before activating a connector in the Askdepth onboarding wizard, run the 15-case conformance test suite (7 positive cases `P1–P7`, 8 negative security cases `N1–N8`):

```bash
npx @askdepth/audience-connector conformance \
  --url http://localhost:3000/askdepth/v1 \
  --secret "$ASKDEPTH_CONNECTOR_SECRET" \
  --unmapped-column password \
  --unmapped-column internal_notes \
  --filter-only-attribute country=US
```

- **Exit code `0`**: All 15 conformance cases passed.
- **Exit code `1`**: One or more conformance checks failed.
- **Exit code `2`**: Runner/preflight failure (invalid CLI flags or unreachable endpoint).
- Add `--json` for structured CI output, or `--case N7` to run a single case.
